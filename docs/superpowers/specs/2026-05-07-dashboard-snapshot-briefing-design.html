Dashboard Snapshot in Morning Briefing

Approved Design Spec 2026-05-07

Add a full dashboard snapshot to the morning briefing so opening the briefing replaces the need to visit the dashboard. Always included, scope matches briefing level.

Architecture

A new shared metrics service that both the dashboard route and the briefing service call. Single source of truth—metrics never drift.

Level-based scoping

LevelScoping
"individual"branch_user_ids = [user_id]
"manager"Query direct reports + self
"leadership"branch_user_ids = None (org-wide)

Integration point

In build_context() (line 713), after existing individual/manager/leadership data gathering, call _query_dashboard_snapshot() and store on ctx.dashboard_snapshot. The BriefingContext dataclass gets a new dashboard_snapshot: dict field. Persisted into briefing_data["dashboard_snapshot"] (existing JSONB column — no migration needed).

AI Narrative Enhancement

The generate_narrative() prompt gets dashboard context so the AI can reference metrics naturally:

Dashboard snapshot:
- Production: 12/18.5 funded this month (65%)
- Efficiency score: 74/100
- Pull-through rate: 68%
- Avg time to close: 32.4 days
- Loans falling behind: 3

- Profitability: 47 funded YTD, $14,100,000 volume
