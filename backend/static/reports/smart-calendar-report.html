Security & Isolation Architecture

98 Multi-Tenant Isolation

  • Database: Every query filters by organization_id. RLS-aware get_db() enforces at connection level.
  • API: _get_org_id(user) called on every authenticated endpoint. Cross-tenant requests return 403.
  • Background Workers: All scheduled jobs (15 staggered cron entries) scoped to individual org iteration.
  • AI Context: Agent prompts, RAG retrieval, and conversation history all filtered by tenant.
  • Webhooks: Delivery logs and subscriptions are org-scoped. Webhook payloads include organization_id.

90 Security Controls

  • Rate Limiting: Redis-backed with async in-memory fallback. LRU eviction with safety (refuses new clients at capacity instead of silent eviction). Sliding window counters per IP per path.
  • Input Validation: nh3 (Rust-based) HTML sanitization. E.164 phone validation. URL scheme whitelisting. Public error masking prevents stack trace leakage.
  • CAPTCHA: Cloudflare Turnstile integration on public booking. Production rejects all requests if secret key missing. Dev bypass for local testing.
  • Conflict Prevention: PostgreSQL advisory locks (non-blocking) with 3 retry attempts. SELECT FOR UPDATE detects competing transactions. Duplicate booking dedup by email+LO+time window.
  • Audit Logging: PII masking (email, phone, name) before persistence. IP + User-Agent captured. Booking source tracked (authenticated, public, AI pipeline).
  • Webhook Verification: SendGrid SENDGRID_WEBHOOK_VERIFICATION_KEY is read from env but not yet applied to inbound webhook validation. Non-blocking.

96 Disaster Recovery & Resilience

  • Circuit Breaker: External service calls (SMS, email, meeting providers) wrapped with circuit breaker pattern.
  • SMS Retry: Exponential backoff at 1s, 2s, 4s intervals. Failure escalation creates CRM tasks.
  • Graceful Degradation: Core booking functions work when AI, telephony, or email providers are unavailable.
  • Audit Retention: Daily cleanup job at 3:17 AM via scheduler_service.py:1308. Configurable retention period.
  • Slot Hold Cleanup: Maintenance endpoint for expired SlotHold records prevents phantom reservations.

Performance & Scalability

Verified Optimizations

  • 14+ composite database indexes on high-traffic queries (org_id + status, org_id + date range, user_id + time window)
  • Pagination enforced: 200-item hard cap on all list endpoints. Cursor-based pagination on analytics.
  • Batch conflict loading: Multi-user availability queries reduced from ~175 queries to ~5-10 via single-pass batch loading.
  • 15 staggered background jobs spread across different cron intervals to prevent thundering herd.
  • Request timing middleware: X-Scheduler-Duration-Ms header on every response. Warnings logged for requests > 1 second.
  • Slot hold TTL: Expired holds auto-cleaned via maintenance endpoint. Prevents phantom reservations from blocking slots.
  • Lazy Redis connection: Per-worker async fallback means rate limiting never blocks booking flow.

Architectural Differentiators

4-Source Calendar Reconciliation

Scheduler appointments + legacy events + manual calendar + Salesforce CRM calendar reconciled in a single availability pass. No other mortgage CRM scheduling system does this.

Compliance-Driven Scheduling

TRID timing, rate lock expiration, and SLA milestones automatically suggest regulatory-driven appointments. The calendar doesn't just schedule — it enforces compliance deadlines.

Advisory Lock Race Prevention

PostgreSQL pg_try_advisory_xact_lock() with 3 retry attempts prevents double-booking under concurrent load. SELECT FOR UPDATE detects competing transactions and returns HTTP 409.

NMLS Licensing Enforcement

Booking flow validates LO NMLS licensing for all 50 states + DC. Blocks appointments in regulated states without valid license. Prevents compliance violations at the point of scheduling.

Graduated No-Show Recovery

4-step escalation (SMS 15min → Email 1h → SMS 24h → Email 72h) with opt-out at every step. Chronic no-show detection (3+ in 90 days) stops auto-recovery. Re-validates state before each step.

Today Dashboard Aggregation

Single endpoint replaces 4 separate frontend calls: appointments + tasks + leads + SLA alerts. All queries indexed, bounded, sequential within single DB session for consistency.
