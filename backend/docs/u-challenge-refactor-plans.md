## PLAN B — Consolidate migrations onto Alembic

The real remaining problem is **not** "set up Alembic" (done). It is:
1. Reconcile model metadata vs. actual prod schema so autogenerate is trustworthy.
2. Flip `SKIP_LEGACY_MIGRATIONS=true` to retire the raw-SQL path without data loss.
3. Catalog/freeze the ~231 orphaned `migrations/*.py` scripts (324 files total;
   only ~59 are referenced by the startup path).

**Safety property in place:** `alembic stamp head` writes only `alembic_version`
(no DDL) — cannot drop tables or lose data. `017_baseline_stamp.upgrade()` is `pass`.

### Stages
- **B0 — schema-diff harness (read-only).** `pg_dump --schema-only` prod → restore
  to scratch DB → `alembic stamp head` → `alembic check`/autogenerate probe.
  Empty diff = Alembic matches prod. Expect a NON-empty diff (legacy raw SQL added
  columns the models have); that diff is the work inventory for B2. **Gates B2.**
- **B1 — resolve dual runners.** Two Alembic invokers exist: `run_migrations.py`
  (subprocess from `start.py`, advisory-locked, exits non-zero on fail — the safe
  prod path) and `alembic_runner.py` (from `app_lifespan.py`). Make `start.py`
  authoritative; downgrade the lifespan call to a read-only head check.
- **B2 — capture drift as Alembic 018+.** `alembic revision --autogenerate` against
  the prod-dump scratch DB → review line by line → write idempotent/guarded ops
  (near no-op on prod, records intent for fresh DBs). Handle enum→VARCHAR
  conversions explicitly. Gate: fresh scratch DB `alembic upgrade head` →
  `alembic check` empty; review prod path via `alembic upgrade head --sql` (no DROP).
- **B3 — new changes are Alembic-only.** Document the rule; add CI guard that fails
  PRs adding raw `CREATE/ALTER TABLE` to `startup_migrations.py`/`init_db.py`.
- **B4 — retire legacy path via kill-switch.** Flip `SKIP_LEGACY_MIGRATIONS=true`
  in staging first (kill-switch already short-circuits `init_db()` + 
  `run_all_startup_migrations()`), soak, then prod. Rollback = unset the var
  (legacy SQL is all `IF NOT EXISTS`, harmless to re-enable). Decide separately on
  the 2 start.py data backfills (`backfill_client_files`,
  `add_multi_tenant_organization_id`) — data not DDL.
- **B5 — catalog/freeze 231 orphaned scripts.** Move to `migrations/_archive/`
  after B4 soaks one release. Do NOT delete (DR / fresh-DB bootstrap record).
- **B6 — decommission `Base.metadata.create_all()` for fresh DBs.** Fresh DBs go
  through `alembic upgrade head` only → guarantees dev/prod parity.
