WHAT IS WORKING CORRECTLY

These patterns are solid and should not be changed:

Security Architecture — SECRET_KEY fails hard in production (RuntimeError). JWT tokens use email hash (SHA-256 truncated to 16 chars) with backward-compatible legacy support. Calendar feed tokens deactivated when user account marked inactive. Weak key rejection validates length (32+) and checks against known defaults.
TCPA Consent Enforcement — All 6 SMS pathways gated with fail-closed consent check. check_sms_consent() returns False on error (never defaults to sending). Covers: no_show_recovery, reminder_service, notification_service, scheduler_service (4 paths).
Prompt Injection Defense — Two-layer regex sanitizer (_INJECTION_PATTERNS + _FREE_TEXT_INJECTION_PATTERNS) with re.IGNORECASE. AI booking context validated against schema before persistence. SSRF protection on webhook URLs blocks private IPs, localhost, and cloud metadata endpoints.
Optimistic Locking — Appointment model uses SQLAlchemy version_id_col. All updates go through ORM (not raw SQL), so StaleDataError fires on concurrent modification. State machine enforces valid transitions via VALID_TRANSITIONS dict checked at 6 call sites.
Idempotency on Appointments — idempotency_key column (String(64), unique, indexed) prevents duplicate bookings from retried API calls.
Unique Constraints — AvailabilitySlot(user_id, day_of_week, organization_id) prevents duplicate availability rows. Partial unique index on appointments prevents double-booking same (user, start, end) excluding cancelled/rescheduled.
Webhook Delivery — Async background dispatch with 3 retries (2s/4s/8s exponential backoff). HMAC-SHA256 signature with constant-time comparison. Deduplication (5-second window per subscription+event_type). Concurrent dispatch via asyncio.gather().
Batch Performance Patterns — load_active_holds() batch-loads all active holds in one query (avoids per-slot DB call). get_weekly_schedule_batch() loads multiple users' availability in single query. Bulk operations pre-load users into users_map.
Circuit Breaker — Consolidated NotificationCircuitBreaker with configurable provider_name. Separate instances for SendGrid and Telnyx. 5-failure threshold, 60-second half-open window.
Centralized Timezone — frontend/src/utils/timezone.js with 15+ exported functions. localStorage cache with 5-min TTL. Fallback chain: API → localStorage → browser. All calendar views (Agenda, Day, Mobile) import from centralized utility.
Booking Widget Accessibility — BookingTypeSelector: proper radiogroup + radio roles. BookingSlotPicker: listbox + option roles with aria-selected. BookingForm: all labels have htmlFor, fields have aria-required, aria-invalid, aria-describedby. Confirmation: aria-live="polite" + SR-only summary.
GDPR Data Compliance — Export endpoint returns full borrower appointment data. Deletion cascades to slot_holds, status_history, reminders. Anonymization uses [Deleted] name and anonymous-deleted@example.com. IP addresses removed from audit API responses.
Pydantic v2 Migration — All schema classes use model_config = ConfigDict(from_attributes=True). No remaining class Config: orm_mode = True patterns.
APScheduler Monitoring — EVENT_JOB_ERROR and EVENT_JOB_MISSED listeners log at ERROR level with exc_info=True.
Correlated Logging — Public booking, confirmation, appointments, and reschedule routes use get_correlated_logger(__name__) for request ID propagation.
State Timezone Mapping — STATE_TIMEZONE_MAP covers 24 states for borrower timezone inference. Falls back to America/New_York when state unknown.
