3. Critical Findings

3A. Major Concerns Critical

1. Product Scope Explosion — 7+ Products in One

Perennia is simultaneously building: (1) mortgage CRM, (2) telephony suite, (3) marketing platform, (4) double-entry accounting system (113 endpoints), (5) recruiting ATS with EEOC compliance (202 endpoints), (6) AI agent platform, (7) compliance engine, (8) video platform, (9) microsite builder. A typical mortgage CRM has 15–20 modules. Perennia has 73.

The accounting and recruiting modules alone represent ~315 endpoints — more than most entire CRMs. Unless these are core revenue drivers, they represent massive misallocated engineering effort.

2. db_migration_routes.py — HTTP Schema Mutation

Security Critical A 2,907-line route file that exposes database schema mutations (CREATE TABLE, ALTER COLUMN, ADD INDEX) via HTTP endpoints. Even with authentication, a compromised token could allow schema destruction via API call. Migrations must never run via HTTP — only from a controlled CLI/deployment pipeline.

3. No SOC 2 Type II Certification

Enterprise Blocker Over 73% of enterprises require SOC 2 reports before vendor onboarding. Aidium explicitly markets SOC 2 Type II as a competitive differentiator. Without this certification, enterprise mortgage lender procurement will not engage. The SOC 2 compliance framework exists in code but has not been audited.

4. Encompass Integration Deferred to Premium Tier

Market Blocker Encompass is used by the majority of US mortgage lenders. Having the integration as "Premium/deferred" while Salesforce is fully built is a prioritization risk. Most mid-to-large lenders will not evaluate a CRM without bidirectional Encompass sync. The code exists (encompass_integration_routes.py, OAuth, field mapping) but is not production-active.

5. 43 Route Files Bypass RLS-Aware get_db()

Tenant Isolation 43 route files define their own local get_db() function instead of importing the RLS-aware version from db.py. While most correctly delegate, the inconsistency means tenant isolation depends on which route file handles a request. Any file that doesn't delegate correctly could leak cross-tenant data.

6. 185+ Ad-Hoc Migration Scripts Bypass Alembic

Schema Management The backend root contains 185+ standalone Python migration scripts (run_*migration*.py, add_*.py) that bypass Alembic's version tracking. The database schema cannot be reliably reproduced from the migration history. Alembic exists (18 version files) but is largely unused.

3B. Questionable Decisions High

7. Silent Route Failure at Startup

All 40+ route registrations in main.py are wrapped in try/except Exception. A broken import in any route file silently drops that module's endpoints. The app starts "successfully" with missing routes, providing misleading health signals. There is no post-startup assertion that critical routes loaded.

8. In-Memory Rate Limiter (Per-Process)

RateLimitMiddleware stores counters in a per-process defaultdict. In multi-worker deployments (multiple uvicorn workers or Railway replicas), each worker has its own counter. A client can bypass rate limits by distributing requests across workers. Redis is already a dependency — the rate limiter should use it.

9. Dual Model Directories with Overlapping Classes

database/models/ (30 files, canonical) and models/ (64 files, secondary) both contain SQLAlchemy models. Four class names appear in both locations (Responsibility, UserResponsibility, CampaignStatus, SyncStatus). The canonical source of truth is ambiguous.

10. 4 Competing Auth Injection Patterns

Auth is fragmented across: (1) main.py canonical functions, (2) auth/dependencies.py lazy proxy, (3) set_dependencies() closure pattern (15 files), (4) local get_current_user wrappers (30+ files). While the February 2026 consolidation improved this significantly (39 files migrated), the remaining fragmentation makes security auditing difficult.

3C. Over-Engineering Medium

11. Full Double-Entry Accounting System (113 Endpoints)

Chart of accounts, AP/AR, journal entries, budget management, bank reconciliation, and a full frontend UI. This is a standalone product embedded inside a CRM. Unless this IS the billing infrastructure for the platform itself, this represents months of engineering on a non-core feature.

12. Recruiting ATS with EEOC Compliance (202 Endpoints)

DISC assessments, EEOC compliance, candidate grading, recruiting dialer, social recruiting, ATS workflows, and a dedicated RecruitPortal/ frontend. Loan officer recruiting is important but rarely requires a full ATS system inside the CRM.

13. 5 Experimental/Frozen Features Still in Codebase

Decision Lab, Circle of Cashflow, Avatar Studio, HR Management, IT Helpdesk — all frozen with no SLA, still consuming route registrations, model definitions, and import overhead. Dead code that should be archived.

8. What You're Doing Right

1. AI Agent Architecture — Best in Class

25 specialized agents with LangGraph orchestration, intent routing that loads only 8–16 tools per request (not all 209), and a hallucination verifier that extracts claims and validates against source data. No mortgage CRM competitor has anything close. The "Decision Engine" prompt framework with concrete confidence thresholds is production-grade system prompt engineering.

2. Telephony Stack — Production-Grade

Telnyx (direct voice/SMS), Vapi/Retell (AI receptionist, outbound), Slybroadcast (RVM), power dialer, IVR, call routing, live whisper, call transcription. This is more comprehensive than Shape's built-in dialer and ahead of most competitors who require third-party integrations. DNC scrub blocking and TCPA compliance are enforced at the code level.

3. Security Posture — Genuinely Hardened

RS256 JWT with Redis blacklisting, 11 security headers (HSTS preload, CSP, COOP, CORP), CSRF double-submit cookie, SQL injection audit clean across 370+ patterns, nh3 HTML sanitization, RLS tenant isolation, field-level Fernet encryption, PII log filtering. The February 2026 hardening sprint was substantial and effective.

4. Decomposition Discipline

main.py went from 29,522 to 1,711 lines. inline_legacy_routes.py from 23,612 to 3,010 lines. 6 large route files decomposed into 30+ focused modules. Auth consolidated from 3 patterns toward 1 canonical pattern. This shows the team recognizes tech debt and addresses it systematically.

5. Compliance Automation

TRID disclosure timing checks, RESPA affiliated business flags, tolerance violation detection (zero and 10% categories), state-specific requirements lookup, loan file auditing, disclosure timeline tracking. Most competitors offer compliance features; Perennia's tool-based approach (8 compliance tools invokable by AI) is more flexible than rule-based competitors.

6. Multi-Tenant Architecture

Proper RLS with TenantContextMiddleware, per-org credential storage for integrations, feature tier gating per organization, SCIM provisioning, SSO/SAML. The infrastructure for enterprise multi-tenancy is solid.

9. Bottom Line

Perennia AI has the most sophisticated AI agent architecture in the mortgage CRM space and a telephony stack that matches or exceeds established competitors. The 25-agent fleet with LangGraph orchestration, intent routing, dynamic tool loading, and hallucination verification is genuinely differentiated — no competitor has this depth of AI integration.

However, the platform is dangerously overextended. 73 feature modules, 3,664 endpoints, 420K lines of backend code — this is the surface area of a company with 50+ engineers, not a startup. The accounting system (113 endpoints) and recruiting ATS (202 endpoints) represent hundreds of hours of engineering on features that don't differentiate a mortgage CRM. Meanwhile, the three things that would actually unlock enterprise revenue — SOC 2 certification, production Encompass sync, and credit bureau monitoring — are either missing or deferred.

The path forward is radical prioritization. Archive frozen experiments. Defer accounting and recruiting to post-launch. Pour engineering into the three enterprise blockers. Publish pricing. Get 10 paying LOs using the AI agents in production and build case studies from real data. The AI is the moat — but a moat without a castle is just a ditch.

Maturity: Late Beta / Early Production-Ready. The platform could be enterprise-ready in 60–90 days with focused execution on the 5 critical items. Without focus, it risks becoming an impressive demo that never ships.
