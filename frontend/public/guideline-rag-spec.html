Overview

Build a full guideline RAG pipeline so Aria and the LO-facing search UI can answer mortgage guideline questions backed by actual indexed guideline documents — not just Claude's training data. The system ingests PDFs from all major agencies (Fannie Mae, Freddie Mac, FHA, VA, USDA) plus specialty programs (Non-QM, AIO, DPA, Construction, Renovation, Reverse Mortgage), chunks them into ~500-token sections, embeds them with pgvector, and serves them through vector search with citations.

StorageEnhance existing GuidelineSection tableAlready has section splitting, AI analysis, keyword search. Just needs pgvector + better chunking.

Retrieval UXSilent injection + cited answersAria silently uses guidelines for routine context; provides citations when LO explicitly asks.

ON guideline_sections USING hnsw (content_embedding vector_cosine_ops)

Inline migration at startup (same pattern as existing checkfirst=True + ALTER TABLE ADD COLUMN IF NOT EXISTS):

  2. Add HNSW index
  3. Add new columns with defaults

Ingestion Pipeline

Improved Chunking

Extends existing split_into_sections() in guidelines_service.py:

  1. Target ~500 tokens (~2000 chars) per chunk instead of the current 2000-char fallback
  2. Sub-section splitting: If a structural section exceeds 500 tokens, split on paragraph boundaries
  3. 50-token overlap between consecutive chunks for context continuity
  4. Preserve metadata: Sub-chunks inherit section_number, section_title, get suffix (e.g., B3-3.1-07.1)
  5. Token counting: Use tiktoken (cl100k_base) for accurate counts

Batch processing: 20 sections at a time to avoid OpenAI rate limits. asyncio.gather for parallelism within each batch.

Content Hash Dedup

On re-ingestion (guideline update):

  1. Compute SHA-256 hash of each chunk's content
  2. Compare against existing chunk_hash values
  3. Only re-embed chunks where hash changed
  4. Delete chunks that no longer exist in new version
  5. Track version via UnderwritingGuideline.version

Automated Scraping

Extend existing scrapers (guideline_updates_scraper.py, mortgage_guidelines_scraper.py). When a new update is detected, download the full document (not just the summary), feed through the same pipeline. Content hash dedup prevents duplicate embedding.

Retrieval & Search

Extending retrieval_service.py

Implement the existing scope="guideline" stub in retrieve():

async def _retrieve_guidelines(self, query_embedding, filters):
    """
    Vector search over guideline_sections table.

    Filters applied BEFORE vector search:
    - agency/source (from UnderwritingGuideline.guideline_type)
    - loan_program
    - category
    - is_active
    - organization_id (for company overlays) OR NULL (for agency)

    Returns: List[GuidelineResult] with:
    - content, section_number, section_title, page_number
    - guideline_name, guideline_type, loan_program
    - similarity_score, overlay_priority
    """

Hybrid Scoring

Primary

pgvector cosine similarity (threshold: 0.3)

Boost

Query terms in section_title or topics add score bonus

Overlay Ordering

Company first (priority 1), then agency (priority 4)

Top-k

Default 5, configurable per tool

Caching

Redis pattern: aria:cache:guideline:{query_hash}:{filter_hash} — TTL 300s. Invalidate on guideline re-ingestion.

Knowledge & Memory Integration

Guidelines are not a standalone corpus — they need to be a first-class part of Aria's knowledge architecture, cross-referenced with borrower memory and unified with the existing AI Knowledge Base.

Context Loading Priority

When Aria assembles context for a conversation, load in this order:

1
Borrower Identity — name, contact info, relationship to LO
2
Active Loan State — loan_program, stage, amount, property
3
Guideline Context (NEW) — top 3 relevant chunks for this loan_program
4
Borrower Preferences — communication, timezone, language
5
Episodic Facts — recent conversation facts from agent_memories
6
Cross-Reference Alerts (NEW) — guideline thresholds vs borrower facts
7
Last Interaction Summary — what happened on the last call

Budget: ~600-800 tokens for guideline context. Same discipline as borrower memory — never exceed context window.

Memory-to-Guideline Cross-Referencing

When loading borrower facts, detect financial facts and auto-cross-reference against guideline thresholds:

Credit Score Match

Fact: "credit score 645" + FHA min 580

→ "Eligible (65 points above minimum)"

Near Threshold

Fact: "credit score 645" + Overlay min 640

→ "Warning: only 5 points above overlay"

DTI Check

Fact: "DTI 42%" + FHA manual max 43%

→ "Within limit but near threshold"

Wait Period

Fact: "Ch7 BK discharged 2023" + FHA 2yr wait

→ "Eligible as of 2025"

Cross-reference rules engine checks:

Credit Score
DTI Ratio
LTV
Derogatory Events
Reserves

Alert format injected at position 6:

⚠ GUIDELINE ALERT: Borrower credit score (645) is only 5 points above your company overlay minimum (640) for FHA. Agency minimum is 580.

Guideline-Derived Insight Storage

When Aria combines borrower data + guideline rules, store derived insights as a special memory type:

# New memory_type for agent_memories
memory_type = "guideline_insight"
# Joins existing: fact, preference, context, insight, directive

What gets stored:

  • Cross-reference results: "Borrower is 5 points above FHA overlay minimum (645 vs 640)"
  • Eligibility determinations: "Eligible for FHA, VA. Not yet eligible for conventional (1yr BK wait)"
  • Overlay conflicts: "Company overlay requires 640 vs agency 580 for FHA"

Guardrails (per existing memory architecture):

!
Tagged as derived: source_type="guideline_cross_reference" — not a verified borrower fact
!
Auto-expires: expires_at = 30 days — financial data changes
!
Superseded on re-calc: If borrower facts update, old insights are superseded
!
Not for compliance: Disclaimer — AI-derived, not official determinations
!
Audit logged: Source guideline, source fact, and derivation logic

Lifecycle:

Created when
  • After call with financial facts
  • Loan stage change
  • Guideline re-ingestion
Recalled when
  • Next conversation with borrower
  • Injected at context position 6
  • Stale (>30d) = recalculated
Invalidated when
  • Borrower facts change
  • Guideline updated
  • 30-day TTL expires
