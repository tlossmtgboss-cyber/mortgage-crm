Voice-to-Submit POS Consent Flow

Complete data flow from Aria voice agent completing a URLA 1003 through borrower consent capture, CRM promotion, and Fannie Mae 3.4 generation.

April 27, 2026 · Architecture Reference

How it works in one paragraph

Aria completes the 1003 over the phone. The voice agent triggers POST /api/v1/pos/voice-complete, which creates a BorrowerApplication record, generates a 7-day magic link, and texts it to the borrower. The borrower taps the link, reviews their data, signs the FCRA credit authorization and E-SIGN disclosure (typed legal name), and submits. On submission, the data promotes into the CRM as a Lead + Loan (stage: APPLICATION), a MISMO 3.4 XML is generated, PDFs are emailed to the loan officer, and a high-priority task is created in their pipeline. Every step writes to the audit trail.

Application Status Lifecycle

DRAFT → PENDING_CONSENT → SUBMITTED → APPLICATION (Loan stage)

If the borrower doesn't act within 7 days, the Day 7 reminder marks the application EXPIRED.

End-to-End Pipeline

1
Voice Agent

Aria Completes the 1003 Over the Phone

The URLA voice agent collects all 9 sections of the Fannie Mae Uniform Residential Loan Application during a phone conversation with the borrower. Data is stored in Redis as an encrypted URLAApplication object.

Storage Redis — urla:{tenant}:loan:{id}
Encryption Fernet symmetric (AES-128-CBC)
TTL 30 days
Sections 9 sections: Personal, Employment, Assets, Liabilities, Property, Loan, Declarations, Demographics, LO Info

When the agent finishes, it triggers:

POST /api/v1/pos/voice-complete

Payload: voice_loan_id, borrower_first_name, borrower_phone, lo_name

2
Database

BorrowerApplication Created, Magic Link Generated

The consent service finds or creates a BorrowerApplication record, generates a PURL magic link token (7-day expiry), and transitions the application to PENDING_CONSENT.

DB Record borrower_applications table
Status DRAFT → PENDING_CONSENT
Token System PURL tokens — purl_access_tokens + purl_workspaces
Token Scope VOICE_REVIEW_SUBMIT (7-day expiry)
Workspace Slug voice-consent-app-{application_id}
Audit Event voice_complete_triggered

Magic link format: https://app.perenniaai.com/apply/voice-review/{token}

3
SMS Delivery

Magic Link Texted to Borrower

The borrower receives an SMS with the review link. TCPA consent is verified before sending. Three follow-up reminders are scheduled.

Provider Telnyx (from +18438838956)
TCPA Gate SMS consent checked before send
Day 1 Reminder "Your application is ready for review..."
Day 3 Reminder "Still needs your signature. Only takes 2 min..."
Day 7 Final "Application will expire soon..." → marks EXPIRED if no action
Tracking sms_delivery_tracker + application_notifications
4
Borrower Consent

Borrower Reviews, Signs Credit Auth & E-Disclosure

The borrower taps the link, reviews their application data, then completes two legally required consent captures. Each requires typing their full legal name.

GET /api/v1/pos/consent/{token}/status
Check completion state + load form data
GET /api/v1/pos/consent/{token}/disclosures
Fetch legal text for both consent blocks
POST /api/v1/pos/consent/{token}/credit-auth
FCRA credit pull authorization
POST /api/v1/pos/consent/{token}/e-disclosure
E-SIGN Act electronic disclosure consent
POST /api/v1/pos/consent/{token}/submit
Final submission (requires both consents)
ConsentRegulationDB TableCaptured Fields
Credit Authorization FCRA § 604(a)(3)(A) credit_authorizations typed_full_name, IP, user_agent, consent_text_hash (SHA-256), consent_text_version, timestamp
E-Disclosure E-SIGN Act (15 USC § 7001) econsent_agreements typed_full_name, IP, user_agent, consent_text_hash, hw/sw requirements shown, right to withdraw shown, paper copy info shown, timestamp
5
CRM Promotion

Lead + Loan Created in Pipeline

On submission, an event subscriber promotes the application into the CRM as first-class records. The loan officer sees it in their pipeline immediately.

Lead Record Created/updated with name, email, phone, employment, income
Loan Record Created with loan amount, purpose, property, type, term
Loan Number POS-{uuid[:8]} (auto-generated)
Loan Stage Promoted to APPLICATION
Task Created "Review submitted 1003 application" (high priority, assigned to LO)
Foreign Keys BorrowerApplication.lead_id → Lead, .loan_id → Loan
6
Documents & Delivery

MISMO 3.4 XML + PDFs Generated & Emailed

The URLA data is serialized to Fannie Mae MISMO 3.4 format. PDFs are generated for the consent records and application summary, then emailed to the loan officer with all attachments.

MISMO Version 3.4.032420210307 (ULAD Extension)
Namespace mismo.org/residential/2009/schemas
Attachments Fannie_Mae_3.4.xml, E-Consent.pdf, Credit_Auth.pdf, Application_Summary.pdf
Storage documents table (category: APPLICATION)

Compliance Coverage

● FCRA (Credit Reporting)

  • Full authorization text displayed before signature
  • Typed legal name captured (click-to-sign)
  • SHA-256 hash of exact text shown preserved
  • IP address + user agent + timestamp recorded
  • Consent text version tracked for audit

● E-SIGN Act (Electronic Consent)

  • Hardware/software requirements disclosed
  • Right to withdraw consent explained
  • Paper copy availability stated
  • Typed legal name captured
  • Separate audit record with full provenance

● TCPA (Telephone Consumer Protection)

  • SMS consent verified before every send
  • Delivery tracking via sms_delivery_tracker
  • Opt-out respected at send time

● ECOA / HMDA (Fair Lending)

  • Demographics collected voluntarily (Section 8)
  • Ethnicity, race, sex fields encrypted
  • Government monitoring info per HMDA requirements
