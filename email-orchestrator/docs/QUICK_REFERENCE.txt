┌──────────────────────────────────────────────────────────────────────┐
│ SYSTEM ARCHITECTURE                                                  │
└──────────────────────────────────────────────────────────────────────┘
Email → Webhook → Queue → Orchestrator → Processors → AI → Database

Processors (in priority order):
  100: LoanApplicationProcessor   - Creates loan records (15 min saved)
   90: SLAMonitorProcessor        - Tracks response times
   80: InvoiceProcessor           - Routes invoices (5 min saved)
   70: DocumentProcessor          - Classifies documents (3 min saved)
   50: ClientInquiryProcessor     - Handles inquiries (10 min saved)

┌──────────────────────────────────────────────────────────────────────┐
│ MONITORING QUERIES                                                   │
└──────────────────────────────────────────────────────────────────────┘
-- Emails processed today
SELECT COUNT(*) FROM email_tracking
WHERE received_at >= CURRENT_DATE;

-- Time saved today
SELECT SUM(time_saved_minutes) FROM automation_time_savings
WHERE triggered_at >= CURRENT_DATE;

-- Success rate by processor
SELECT * FROM processor_performance
ORDER BY total_runs DESC;

-- SLA compliance this week
SELECT
  COUNT(*) FILTER (WHERE sla_status = 'ok') * 100.0 / COUNT(*) as compliance
FROM email_response_tracking
WHERE received_at >= CURRENT_DATE - 7;

┌──────────────────────────────────────────────────────────────────────┐
│ TROUBLESHOOTING                                                      │
└──────────────────────────────────────────────────────────────────────┘
Emails not processing?
  → Check webhook subscription is active
  → Check logs: tail -f logs/error.log
  → Enable debug: LOG_LEVEL=debug npm start

High error rate?
  → Check AI API: verify ANTHROPIC_API_KEY
  → Check DB connection: verify DATABASE_URL
  → Review errors: SELECT * FROM email_processing_errors LIMIT 10

No time savings data?
  → Check: SELECT COUNT(*) FROM automation_time_savings
  → Verify processors are running: GET /api/status
